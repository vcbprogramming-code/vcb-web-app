## 1. ภาพรวมของโมดูล

System Map เป็น **ตัวแสดงผลแบบคงที่ (static renderer)** — ไม่ใช่ระบบที่มีข้อมูล
สด ไม่มีฐานข้อมูล ไม่มี API ของตัวเอง — ที่วาดแผนผัง "งานไหลอย่างไรในบริษัท
VCB" (ผู้รับเหมาก่อสร้างงานโยธา/ทางหลวงของไทย) ให้ดูเป็นแผนภาพ swimlane
(เลนแนวนอนตามลำดับเวลา) พร้อมจุด (node) ของแต่ละขั้นตอนงาน และเส้นเชื่อม
ข้ามเลนที่แสดงว่าขั้นตอนใดกระตุ้น/ป้อนข้อมูล/ขึ้นกับขั้นตอนใด

ข้อมูลทั้งหมดที่แผนผังนี้แสดง — เลน 10 เลน, โหนดกระบวนการ 79 โหนด,
เส้นเชื่อมข้ามเลน 129 เส้น, และทะเบียนฟังก์ชัน 158 รายการใน 7 แผนก —
ถูก **เขียนเป็นค่าคงที่ (hardcoded)** ไว้ในซอร์สโค้ด React ที่ไฟล์ใต้
`src/data/` และถูก "คอมไพล์" เข้าไปในบันเดิลตอน build (`npm run build`)
ไม่มีการดึงข้อมูลจากเซิร์ฟเวอร์ ไม่มีการล็อกอินที่มีผลต่อสิ่งที่แสดง
ผู้ใช้ทุกคนเห็นแผนผังเดียวกันทุกประการ

เนื้อหาทางธุรกิจที่แผนผังนี้แทน (Mango ERP มีโมดูลอะไรบ้าง, ขั้นตอนไหนเป็น
ERP ขั้นตอนไหนเป็นงานมือ, ใครทำอะไร) มีการอธิบายละเอียดยิ่งกว่าในเอกสาร
`ORIGINAL CODE/system-map/COMPANY_OPERATING_MODEL.md` — เอกสารนั้นคือ
"โมเดลธุรกิจ" ที่แผนผังนี้แสดงผลออกมา ส่วนเอกสารฉบับนี้อธิบาย **การทำงาน
ของตัวแอป React** ที่แสดงโมเดลนั้น

### สถาปัตยกรรมโดยสรุป

- **Stack**: React 18 + Vite 5 + Tailwind CSS 3 (JavaScript ล้วน — ไม่มี
  TypeScript อีกต่อไปหลัง port, ดู §6)
- **State management**: React Context + `useState` เดียว (`src/store.jsx`)
  ไม่มี Redux, ไม่มี React Router (แอปเป็นหน้าเดียว — single view)
- **การแสดงแผนภาพ**: SVG ที่เขียนมือ (hand-written) ล้วน — ไม่มีไลบรารีชาร์ต/
  กราฟใด ๆ (ห้ามตาม `TECH_STACK.md` ของโปรเจกต์)
- **ไม่มี backend ของตัวเอง**: ไม่มี module API client, ไม่มี `fetch` เฉพาะ
  โมดูล, ไม่มีตารางฐานข้อมูล — ยืนยันซ้ำใน §5
- **Providers ที่ห่ออยู่** (`src/main.jsx`): `ThemeProvider` → `I18nProvider`
  → `AuthProvider` → `StoreProvider` → `App` — `AuthProvider` มีไว้เพียงให้
  แถบบนบอกชื่อผู้ใช้ที่ล็อกอินอยู่ (เหมือนโมดูลอื่นทุกโมดูล) แต่ **ไม่ได้ปิดกั้น
  การเข้าถึงใด ๆ** เพราะ authentication ในโมดูลนี้ใช้เพื่อระบุตัวตนอย่างเดียว
  ไม่ใช่เกต (gate) — ดู §5

## 2. รายการฟังก์ชันทั้งหมด (มุมมอง/ไดอะแกรม/ปฏิสัมพันธ์)

แอปนี้เป็น "แอปหน้าเดียว" (single view, ไม่มี `BrowserRouter`) สิ่งที่ดู
เหมือนหน้าจอแยกกัน — แผนภาพหลัก, ภาพรวมระดับบน (L0), การ trace เส้นทาง,
ทะเบียนฟังก์ชัน — ล้วนเป็น **overlay (ชั้นซ้อน)** เหนือแผนที่เดียวกัน สลับ
เปิด-ปิดด้วย state ใน store ไม่ใช่ route ที่มี URL ของตัวเอง

รายการฟังก์ชันหลักมีดังนี้ (แต่ละอันมีรายละเอียด logic ใน §3):

1. **แผนที่ swimlane หลัก (Lanes)** — แสดงเลน 10 เลน x โหนด 79 โหนด พร้อม
   ลูกศรเชื่อมภายในเลน
2. **เส้นเชื่อมข้ามเลน (SvgEdges)** — วาดเส้น 129 เส้นเชื่อมระหว่างโหนดคนละเลน
   ด้วย SVG ที่คำนวณพิกัดจาก DOM จริง
3. **ตัวกรองชั้นข้อมูล (Layer filter)** — ทั้งหมด / เฉพาะ ERP / เฉพาะงานมือ
4. **ตัวกรองแผนก (Department filter)** — เลือกแผนกใดแผนกหนึ่งจาก 7 แผนก
5. **สลับแสดง/ซ่อนเส้นตรง-เส้นประ (Direct/Indirect toggle)**
6. **โหมดโอกาส AI (AI Opps mode)** — ไฮไลต์โหนดที่มีข้อเสนอ automation ด้วย AI
7. **แผงข้อมูลด้านข้าง (Sidebar)** — รายละเอียดเมื่อคลิกโหนด (steps/tasks,
   connections, AI opps)
8. **แถบเอกสารหน้างาน (DocsLayer)** — แถวกล่องเอกสารกระดาษ (Doc 02A, 02B, …)
9. **คำอธิบายสัญลักษณ์ (Legend)** — กล่องพับเก็บได้มุมล่างซ้าย
10. **โหมดติดตามเส้นทาง (Focus / Linear Trace)** — คลิกแล้ว "ซูม" ไปดูสาย
    เหตุ-ผลของโหนดเดียวแบบเป็นแผนภูมิต้นไม้
11. **ทะเบียนฟังก์ชัน (Function Registry)** — ตารางค้นหาได้ 158 รายการ
    แยกตามแผนก
12. **ภาพรวมระดับ L0 (Overview / 5-stage view)** — การ์ดสรุป 5 ขั้นตอนใหญ่ +
    ฟังก์ชันสนับสนุน 4 กลุ่ม — **มีอยู่ในโค้ดสมบูรณ์แต่ไม่เคยแสดงบนหน้าจอจริง**
    (ดูหมายเหตุสำคัญใน §3.10)
13. **แถบบนสุด (TopBar)** — แบรนด์ + ปุ่มควบคุมตัวกรอง/โหมดต่าง ๆ ทั้งหมด

ไม่มีการซูม/แพน (zoom/pan) ในความหมายกล้อง — การ "ซูม" คือการสลับไปแสดง
แผนภูมิ trace ใหม่ (overlay เต็มจอ) ไม่ใช่การซูมภาพเดิม ผู้ใช้เลื่อนดูแผนที่
หลักด้วยการ scroll ปกติของเบราว์เซอร์ในกล่อง `#mapScroll`

## 3. รายละเอียดแต่ละฟังก์ชันและ Logic การทำงาน

### 3.1 แผนที่ swimlane หลัก — `src/components/Lanes.jsx`

**ทำอะไรได้**: แสดงเลนแนวนอน 10 เลน (`LANES` จาก `src/data/lanes.js`,
1,636 บรรทัด) เรียงจากบนลงล่างตามลำดับวงจรชีวิตโครงการ แต่ละเลนมีป้ายชื่อ
เลนทางขวา (แปลด้วย `tLane()`) และแถวโหนดเรียงซ้ายไปขวา คั่นด้วยลูกศร SVG
ระหว่างโหนดที่ต่อเนื่องกันในเลนเดียวกัน (ไม่ใช่ระหว่างโหนดที่มี
`standalone: true`)

**โครงสร้างข้อมูลโหนด** (ตาม `src/lib/derived.js` บรรทัด 4-8):
```
lane node = { id, type: 'erp'|'manual', dept, label, sub, desc, module,
              items[], unverified, dept2?, loc?, standalone?, routes? }
```
- `type: 'erp'` → กล่องพื้นทึบสี ขอบบนหนา 3px (สีแผนกจาก `DEPTS[dept].color`)
- `type: 'manual'` → กล่องขอบประ (dashed) พื้นเข้ม (โหมดมืด) หรือพื้นขาวขอบ
  หนาขึ้น (โหมดสว่าง — ดูหมายเหตุ light-mode ใน PORT_NOTES §"dashed border")
- `unverified: true` → แสดงไอคอน ⚠ มุมล่างซ้าย (ข้อมูลเบื้องต้น ยังไม่ยืนยัน)
- `loc: 'site'` → แสดงไอคอน 📍 มุมล่างขวา (ทำงานที่หน้างานไม่ใช่ HQ)
- `dept2` → แผนกที่สอง (สนับสนุน/ตรวจสอบ) แสดงจุดกลมเล็กมุมบนซ้ายด้วยสี
  ของแผนกที่สอง
- `standalone: true` → ไม่มีลูกศรเชื่อมกับโหนดก่อนหน้าในเลนเดียวกัน

**โหนดปลายทาง (terminal node)**: คำนวณตอนโหลดโมดูล (บรรทัด 17-26 ของ
`Lanes.jsx`) — หาโหนด ERP ตัวสุดท้ายของแต่ละเลนที่ไม่มีเส้นเชื่อมข้ามเลน
ออกไปไหนต่อ (`!crossFromSet.has(last.id)`) แล้วติด class `.node-terminal`
ซึ่งใน `index.css` จะแสดงข้อความ `■ EXIT` ด้วย `::after` pseudo-element
(ไม่มีทางแปลงเป็น Tailwind utility ได้ ดู PORT_NOTES)

**การคลิกโหนด**: ถ้าโหมด "โหมดติดตาม" (`focusArmed`) เปิดอยู่ → เรียก
`openFocus(node)` (เปิด trace overlay) ไม่งั้นเรียก `selectNode(node)`
(เปิด sidebar)

**การไฮไลต์เมื่อเลือกโหนด**: ฟังก์ชัน `connectedSet(nodeId)` (export จาก
ไฟล์เดียวกัน, บรรทัด 30-40) หาเซตของโหนดที่เชื่อมโดยตรงกับโหนดที่เลือก
(ทั้งขาเข้าและขาออกจาก `CONN_FROM`/`CONN_TO`) โหนดในเซตนี้ได้ outline
สีส้ม (`highlighted`), โหนดนอกเซตถูกจาง (`dimmed`, opacity 0.18 +
grayscale) — ใช้งานเฉพาะตอนไม่ได้เปิด trace overlay (`!s.focusShow`)

### 3.2 เส้นเชื่อมข้ามเลน — `src/components/SvgEdges.jsx`

**ทำอะไรได้**: วาดลูกศร SVG เชื่อมโหนดที่อยู่คนละเลนตามข้อมูล `CROSS_CONNS`
(781 บรรทัดใน `src/data/crossConns.js`, 129 เส้น) ทับอยู่บนแผนที่หลัก

**Logic การทำงานโดยละเอียด**:
- เป็นโค้ด **imperative ล้วน** (ไม่ใช่ JSX) เพราะเป็น pass แบบ "วัดก่อนวาด"
  (measure-then-paint) — พิกัดของโหนดรู้ได้ก็ต่อเมื่อ layout เสร็จแล้วเท่านั้น
  จึงไม่มีทางเขียนเป็น JSX ที่ render พร้อม commit เดียวกันได้
- ฟังก์ชันหลักคือ `drawArrows(selectedNodeId)` (export) ถูกเรียกจาก
  `useLayoutEffect` สองจังหวะ: ทันทีผ่าน `requestAnimationFrame` และอีกครั้ง
  หลัง 250ms (`setTimeout`) เพื่อจับ reflow ที่มาช้า (เว็บฟอนต์โหลดเสร็จ,
  label ตัดบรรทัดใหม่) ที่จะขยับพิกัดที่วัดไว้
- **จุดยึดพิกัด (origin)**: SVG overlay (`#svgOverlay`) คำนวณพิกัดทุกจุด
  โดยอ้างอิงกับมุมซ้ายบนของ `#lanesWrap` (`r.left - wrapRect.left`) และตั้ง
  `left`/`top` ของ SVG เองใหม่ทุกครั้งที่ redraw จาก `wrapRect` (ไม่ใช่ตั้งครั้ง
  เดียวตอน mount) — เพราะ `.map-scroll` ต้องเป็น `position: relative` เพื่อ
  เป็น containing block ให้ SVG ที่ตำแหน่ง absolute (ดูหมายเหตุ "ต้อง pin
  origin" ใน PORT_NOTES — บั๊กที่เคยเกิดตอน port ทำให้ลูกศรเลื่อนขึ้นไป
  164px)
- **การจัดเส้นทาง (routing)** แบ่งสองแบบตามประเภทเส้นเชื่อม:
  - **เส้นตรง (trigger/feeds)**: สีฟ้า (`#38bdf8`), เส้นทึบ
    - ถ้าปลายทางกับต้นทางอยู่แถวใกล้กัน (`|tr.top - fr.bottom| < 40`) →
      "โค้งข้ามหลังคา" (arch over the top) ด้วยเส้น L-shape สามท่อน
    - ถ้าไม่ใช่ → วิ่งผ่าน "ทางเดินซ้าย" (left corridor ที่ x=50px) ด้วยมุมโค้ง
      รัศมี 9px
  - **เส้นประ (conditional/deferred)**: สีเหลือง (`#ffc233`), เส้นประ
    `8 5` — ใช้ orthogonal routing บน-ล่างแบบมีราง (mid-rail) โค้งมน
    ถ้ามีหลายเส้นเข้าจุดหมายเดียวกัน (`inCntByTarget`) จะ "กระจายพัด"
    (fan-out) ข้ามขอบบนของกล่องปลายทาง โดยเว้นระยะ 14px ต่อเส้น
- **การกรอง**: ฟังก์ชัน `isNodeFiltered(el)` อ่าน class บน `<body>`/`#lanesWrap`
  โดยตรงจาก DOM (ไม่ใช่จาก React state) เพื่อตัดสินว่าโหนดถูกซ่อนโดย layer
  filter (`body.layer-erp`/`body.layer-manual`) หรือ department filter
  (`.lanes-wrap.dept-active` + ไม่มี class `.dept-show`) หรือไม่ — ถ้าทั้งต้น
  ทางและปลายทางถูกกรองพร้อมกัน เส้นนั้นไม่ถูกวาดเลย ถ้าถูกกรองแค่ฝั่งเดียว
  จะวาดแต่จางลง (opacity 0.1)
- **การไฮไลต์เมื่อเลือกโหนด**: ถ้ามีการเลือกโหนด เส้นที่ไม่เกี่ยวข้องกับโหนด
  นั้นจะ opacity 0 (ซ่อนสนิท) เส้นที่เกี่ยวข้อง opacity 1 และหนาขึ้นเป็น
  stroke-width 3
- **หัวลูกศร (marker)**: สร้าง `<marker>` element แยกตามประเภทเส้น 4 ประเภท
  (trigger/feeds/deferred/conditional) วางไว้ใน `<defs>`
- เส้นทึบวาดก่อน เส้นประวาดทับทีหลัง เพื่อให้เส้นทางอ้อมอ่านง่ายกว่าทับ
  เส้นทางตรง

### 3.3 ตัวกรองชั้นข้อมูล / แผนก / เส้นทางตรง-อ้อม — `src/components/TopBar.jsx`

**ทำอะไรได้**: แถบควบคุมใต้แบรนด์บาร์ (ไม่ใช่ AppBar ที่ใช้ร่วมกับโมดูลอื่น
— โมดูลนี้เขียนแถบตัวกรองของตัวเอง) มีสองแถว:

แถวที่ 1:
- **ปุ่มเลเยอร์**: ทั้งหมด / ⚙️ ERP / 📋 งานด้วยมือ — เรียก `s.setLayer(...)`
  ตั้งค่า `activeLayer` เป็น `'all' | 'erp' | 'manual'` ค่านี้กลายเป็น class
  `body.layer-erp`/`body.layer-manual` ที่ `index.css` และ `SvgEdges.jsx`
  ใช้กรอง (ดู §3.2)
- **ปุ่ม — เส้นตรง / ╌ เส้นประ**: toggle `hideDirect`/`hideIndirect` — ซ่อน
  ประเภทเส้นเชื่อมนั้น ๆ ทั่วทั้งแผนที่ (class `body.hide-direct`/
  `body.hide-indirect`)
- **ปุ่ม 📋 ทะเบียนฟังก์ชัน**: เปิด/ปิด Function Registry overlay
  (`s.toggleRegistry()`)
- **ปุ่ม 🤖 โอกาส AI**: toggle `showAiMode` — เปิด class `body.ai-mode` ซึ่งทำ
  ให้ badge AI ✨ บนโหนดที่มี `AI_OPPS[node.id]` ปรากฏ พร้อม box-shadow
  เรืองแสงสีม่วง (`#a78bfa`)

แถวที่ 2:
- **แถบแผนก (dept bar)**: ปุ่ม 7 ปุ่มตามลำดับคงที่
  `['eng','pm','proc','fin','acc','asset','hr']` แต่ละปุ่มมีสีพื้นหลังจาก
  `DEPTS[k].color` คลิกแล้วเรียก `s.toggleDept(k)` — ถ้าคลิกซ้ำแผนกเดิม
  จะยกเลิกตัวกรอง (toggle) มีปุ่ม ✕ ล้างตัวกรองทั้งหมด (`s.clearAll`)
  ซึ่งรีเซ็ตทุก state กลับค่าเริ่มต้น (ปิด registry, ปิด trace, ล้างการเลือก,
  ล้างตัวกรองทั้งหมด)

### 3.7 โหมดติดตามเส้นทาง (Focus / Linear Trace) — `src/components/FocusTrace.jsx`

**ทำอะไรได้**: เมื่อกดปุ่ม "⤢ ติดตาม" ในแผง sidebar (หรือเปิดโหมด focus แล้ว
คลิกโหนด) จะเปิด overlay เต็มจอ (`z-[65]`) แสดงแผนภูมิต้นไม้ (tree) ของ
โหนดที่โฟกัส พร้อมทุกสิ่งที่ไหลเข้า (ซ้าย) และไหลออก (ขวา) จนถึงระยะ 5 hop
(`MAXD = 5`)

**Logic การทำงานโดยละเอียด** (ทั้งหมดในฟังก์ชัน `layoutAndRenderFocus`,
ไม่พึ่ง DOM จนกว่าจะ paint จริง):

1. **สร้าง adjacency** (`fEdges()`): รวมลำดับภายในเลน (ไม่นับโหนด
   `standalone`) กับ `CROSS_CONNS` ที่ไม่ใช่ feedback แล้วจัดอันดับ
   (`rank`) — เส้นที่ตรงไปที่ "จุดรวม" อย่าง PM Dashboard (`n-pm-dash`)
   หรือ Finance (`n-fin`) จะได้ rank 2 (ต่ำสุด) เพื่อไม่ให้เส้นเหล่านี้
   "แย่ง" กลายเป็นเส้นหลัก (spine) ของแผนภูมิ
2. **จัดคอลัมน์ตามระยะ hop**: BFS ทั้งขาไป (downstream) และขากลับ
   (upstream) จากโหนดโฟกัส คอลัมน์ 0 = โฟกัส, คอลัมน์บวก = ปลายน้ำ,
   คอลัมน์ลบ = ต้นน้ำ — โหนดที่เป็นทั้ง "ป้อนเข้า" และ "อยู่ปลายน้ำที่เข้าถึง
   ได้อีกทาง" (`compactFeeders`) จะถูกจัดให้อยู่ฝั่งปลายน้ำเท่านั้น ป้องกัน
   การวาดซ้ำสองที่
3. **จัดแถวแบบ greedy packing**: เส้นหลัก (spine — เส้นทางตรงสุดจากโฟกัส
   ทั้งสองทิศ) ได้แถว 0 เสมอ ส่วนโหนดอื่นใช้ BFS แล้ว "หาแถวว่างที่ใกล้พ่อ
   แม่ที่สุด" ทีละคอลัมน์ (`occ` เป็น Set ของแถวที่ใช้แล้วต่อคอลัมน์)
4. **คำนวณพิกัดจริง**: ค่าคงที่ `COLW=212, ROWH=86, CW=158, CH=66, PAD=34`
   — พื้นที่ด้านบน (`TOPBAND`) จองไว้เพิ่มถ้ามีเส้น feedback ที่ต้องวิ่งข้าม
   มากกว่า 1 คอลัมน์ (สูงสุด 6 เส้น × 9px + 22)
5. **วาดเส้นเชื่อม 3 แบบ**:
   - **เส้นไปข้างหน้าปกติ**: ออกจากขอบขวา เข้าขอบซ้ายของกล่องถัดไป
     ผ่าน "เลนแนวตั้ง" (`laneFrac`) ที่แยกเส้นตรงกับเส้นเงื่อนไขไม่ให้ทับกัน
     เมื่อวิ่งข้ามช่องว่างเดียวกัน
   - **เส้น feedback แนวตั้งในคอลัมน์เดียวกัน**: เส้นตรงขึ้น/ลง
   - **เส้น feedback ระยะไกล**: วิ่งออกไปที่ "ร่องข้าง" (side gutter) แล้ว
     jog กลับเข้า ปรับ offset สลับซ้าย-ขวาไม่ให้ซ้อนทับกันเป๊ะ
   สีเส้น: feedback=น้ำตาลทอง (`#c9a14a`) ประ, conditional=น้ำตาลทองประ,
   ปกติ=ฟ้าสว่างถ้าเชื่อมกับโฟกัสโดยตรง (`hot`) มิฉะนั้นเทาเข้ม
6. **วาดกล่องโหนด** (`.fnode`) ด้วย `document.createElement` + `textContent`
   ล้วน (ไม่ใช้ `innerHTML`) ผูก event `mouseenter`/`mouseleave` เพื่อไฮไลต์
   เฉพาะเส้นของกล่องนั้น (`hlFocusEdges`/`clrFocusEdges`) และ `click` เพื่อ
   trace ใหม่จากกล่องนั้น (โฟกัสเปลี่ยน, ประวัติเพิ่มเข้า `focusTrail`)
7. **เลื่อนจอ**: `requestAnimationFrame` เลื่อน scroll ไปยังตำแหน่งโฟกัส
   โดยเว้นคอลัมน์ต้นน้ำ 1 คอลัมน์ให้เห็นทางซ้าย

**แถบด้านบน overlay**: ปุ่ม "🗺️ แสดงบนแผนที่ใหญ่" (`s.showOnBigMap`) ปิด
trace แล้วเลือกโหนดเดิมบนแผนที่หลักพร้อม scroll ไปหา, ปุ่ม "✕ ปิด"
(`s.closeFocus`) **แถบ breadcrumb ประวัติการติดตาม** (`focusTrail`, เก็บ
สูงสุด 7 รายการล่าสุด ใน `store.jsx` ฟังก์ชัน `pushTrail`) ให้คลิกย้อนกลับ
ไปโฟกัสรายการก่อนหน้าได้

**หมายเหตุ**: ฟีเจอร์ `renderFocusDetail()` / แผงรายละเอียดข้าง (`.focus-
detail`) ของต้นฉบับ **ถูกลบทิ้งไปเลย ไม่ใช่แค่ไม่ render** เพราะไม่เคยถูก
เรียกจากที่ไหนในต้นฉบับเลย และ markup ของ focus layer ก็ไม่มีคอนเทนเนอร์
`.focus-main`/`#focusDetail` ให้มันแสดงผลได้อยู่แล้ว — เป็นจุดเดียวที่การ
port "แก้ไข" มากกว่า "ก็อปปี้" (ดู PORT_NOTES §"Behaviour differences")

### 3.8 ทะเบียนฟังก์ชัน (Function Registry) — `src/components/FunctionRegistry.jsx`

**ทำอะไรได้**: overlay เต็มจอ (`z-[450]`, สูงกว่า focus trace) แสดงตาราง
ฟังก์ชัน 158 รายการจาก `FUNCTION_REGISTRY` (`src/data/functionRegistry.js`,
1,144 บรรทัด) แยกตาม 7 แผนก + มุมมองพิเศษ "หน้างาน" (`__site__`)

**โครงสร้างข้อมูลแถว**: array 5-6 ช่อง
`[code, name, erpType, module, notes, isExternalEntry?]`

**Logic การทำงาน**:
- **แท็บแผนก**: `all` (ทุกแผนก) + แผนกทั้ง 7 (จาก `DEPT_META`) + `__site__`
  (แสดงเฉพาะฟังก์ชันที่อยู่ใน `FUNCTION_LOC` set — ฟังก์ชันที่ทำที่หน้างาน)
- **ค้นหา** (`fnSearch`): ตรวจ match กับ code, name, หรือ notes
  (case-insensitive) ผ่านฟังก์ชัน `matches(fn, q)`
- **ปุ่ม "📍 เฉพาะหน้างาน"** (`siteOnlyRegistry`): กรองซ้ำเฉพาะฟังก์ชันที่
  อยู่ใน `FUNCTION_LOC`
- **การนับสถิติ** (`statsText`): จำนวนที่แสดง, จำนวน "จุดเข้าภายนอก"
  (`f[5] === true`), จำนวน "งานหน้างาน" (`FIELD_ACT_CODES.size`), และถ้า
  เปิดโหมด AI จะโชว์จำนวนที่มีโอกาส AI ด้วย
- **แถวมี badge ERP/Non-ERP** ตาม `fn[2]` (trim + lowercase เทียบกับ
  `'erp'`)
- **โหมด AI ในตาราง**: ถ้า `showAiMode` เปิดอยู่ (มาจากปุ่มบน TopBar) และ
  แถวนั้นมีข้อมูลใน `FUNCTION_AI[code]` จะแสดงบรรทัดข้อเสนอ automation
  (ภาษาไทย/อังกฤษตามภาษา UI) พร้อมชื่อเครื่องมือ
- **การเปิดจาก sidebar** (`openRegistryToFunction`): ตั้ง `fnHighlightCode`
  แล้ว `useEffect` (มี `setTimeout` 60ms ให้ DOM render ตารางเสร็จก่อน)
  ค้นหาแถวที่ตรง code, `scrollIntoView` แล้วติด class ไฮไลต์ชั่วคราว
  (`fn-row-hl`) 2.8 วินาทีแล้วลบออก
- **แปลภาษา**: `tRegistryRow(lang, code)` คืนคู่ `[name, notes]` ภาษาไทย
  จาก `LANG_TH.registry[code]` ถ้ามี ไม่งั้น fallback เป็นค่าอังกฤษดิบใน
  `fn[1]`/`fn[4]`

**หมายเหตุบั๊กที่แก้ไข**: ต้นฉบับมี `ReferenceError` เมื่อเปิดนับจำนวน
ฟังก์ชันที่มีโอกาส AI พร้อมกับเปิด registry อยู่ — พอร์ตนี้แก้ด้วยการคำนวณ
`aiAllCount` อย่างถูกต้องแทน (จุดเดียวที่ตั้งใจแก้บั๊กมากกว่า mirror
พฤติกรรมเดิม)

## 4. ยืนยันว่าไม่มีฐานข้อมูล/API

ตามมาตรฐานสถาปัตยกรรมของโปรเจกต์ (`ARCHITECTURE_STANDARD.md`): **"System
Map | none — static renderer"** — ยืนยันจากหลักฐานต่อไปนี้:

1. **`system-map/supabase/README.md`** ระบุตรง ๆ ว่า "System Map — no
   database needed" และ "There is deliberately no `schema.sql` here" —
   เหตุผลคือฝั่ง Apps Script เดิมมีแค่ 13 บรรทัดที่หน้าที่เดียวคือ serve
   หน้า HTML คงที่ (`doGet` → `Index.html`) ไม่มี `SpreadsheetApp`, ไม่มี
   `PropertiesService`, ไม่มี `DriveApp` ที่ใดเลยในนั้น เนื้อหาแผนที่อยู่ใน
   React source ใต้ `src/data/` และถูกคอมไพล์เข้าบันเดิลตอน build
2. **ไม่มี module API client ของตัวเอง**: ตรวจสอบทั้งโปรเจกต์แล้วไม่พบการ
   เรียก `fetch`/axios ไปยัง backend เฉพาะโมดูล — คำขอเดียวที่มีในระบบคือ
   ของ `AuthProvider` (`/api/auth/me`) ซึ่งใช้เพื่อแสดงชื่อผู้ใช้ที่ล็อกอิน
   ในแถบบนเท่านั้น ยิงเฉพาะเมื่อมี token อยู่แล้ว และดักข้อผิดพลาดทิ้งถ้า
   ล้มเหลว (ไม่กระทบการแสดงผลใด ๆ ของแอป)
3. **ไม่มีการ gate ด้วย role/สิทธิ์**: ค้นคำว่า "role" ทั้งซอร์สโค้ดพบเพียง
   `role="button"` ซึ่งเป็น ARIA attribute บน `<span>` ที่คลิกได้ ไม่ใช่
   การตรวจสอบสิทธิ์ผู้ใช้แต่อย่างใด — ผู้ใช้ทุกคนเห็นแผนที่เดียวกันทุก
   ประการ ถ้าต้องการควบคุมการเข้าถึงในอนาคต ควรทำที่ระดับ "ปุ่มเข้าโมดูล"
   บนพอร์ทัล ไม่ใช่ในโมดูลนี้
4. **package.json** ประกาศตัวเองตรง ๆ ว่า *"VCB System Operating Map —
   interactive swimlane map of company systems. Static renderer: no
   database, no API."*
5. **ผลคือ migration ทำได้ง่ายมาก**: แค่ `npm install && npm run build`
   แล้ว deploy โฟลเดอร์ `dist/` ไปยัง static host (เช่น Vercel) แล้วชี้
   ปุ่มบนพอร์ทัลไปที่ URL ใหม่ — ไม่ต้องมี Supabase project, ไม่ต้องมี
   auth, ไม่ต้องมี data import ใด ๆ ทั้งสิ้น

**ถ้าในอนาคตต้องการให้แก้ไขแผนที่ผ่านหน้าเว็บได้** (ไม่ใช่แก้ในโค้ด)
`supabase/README.md` แนะนำไว้ว่าจุดนั้นคือจังหวะที่ควรเพิ่ม schema — ใช้
เอกสาร `jsonb` หนึ่งตัวบวกตาราง editors ก็เพียงพอ (รูปแบบเดียวกับที่ใช้ใน
`../../../sop/FOR DEPLOYMENT TEAM/supabase/schema.sql`) แต่ตราบใดที่ยังไม่
มีความต้องการนั้น การเพิ่มฐานข้อมูลมีแต่ต้นทุนไม่มีประโยชน์

## 6. ข้อจำกัดและสิ่งที่ยังไม่รองรับ (จาก PORT_NOTES.md)

1. **ภาพรวม L0 (Overview) เข้าไม่ถึงผ่าน UI จริง** — ดูรายละเอียดใน §3.10
   โค้ดสมบูรณ์แต่ไม่มีปุ่มเรียกในหน้าจอที่เผยแพร่ ทั้งในต้นฉบับ Apps Script
   และในพอร์ต React
2. **`FocusDetail` (แผงรายละเอียดข้าง trace) ถูกลบทิ้งถาวร** — ไม่ใช่แค่ไม่
   render, เพราะไม่เคยมีทางเรียกได้ตั้งแต่ต้นฉบับ (§3.7)
3. **ไม่มีการแก้ไขแผนที่ผ่านหน้าเว็บ** — ข้อมูลทั้งหมดฝังในซอร์สโค้ด แก้ไข
   ได้เฉพาะโดยแก้ไฟล์ใน `src/data/` แล้ว build ใหม่ (ไม่มีหน้าจอ admin/
   editor ใด ๆ) — ถ้าต้องการให้แก้ไขได้ในอนาคต ต้องเพิ่ม Supabase schema
   ตามที่ระบุใน §4
4. **ไม่มี BrowserRouter / ไม่มี URL แยกตามหน้าจอ** — ทุก "หน้าจอ" เป็น
   overlay สลับด้วย state เท่านั้น ไม่สามารถแชร์ลิงก์ตรงไปยังโหนดหรือมุมมอง
   ใดมุมมองหนึ่งได้ (deep-linking ไม่รองรับ)
5. **`AuthProvider` ไม่ gate อะไรเลย** — ใส่มาเพียงให้แถบบนแสดงชื่อผู้ใช้
   เหมือนโมดูลอื่น ไม่มีผลต่อสิทธิ์การมองเห็นเนื้อหาใด ๆ
6. **TypeScript ถูกถอดออกทั้งหมด**: ไฟล์ `.ts`/`.tsx` 35 ไฟล์แปลงเป็น
   `.js`/`.jsx`, ลบ `tsconfig.json`, `typescript`, `@types/*` ทั้งหมด, Vite
   ลดเวอร์ชันจาก 6 เป็น 5 — ไฟล์ `src/data/types.ts` เดิม (มีแต่
   interface/type alias) ถูกลบไปโดยไม่มีไฟล์แทนที่ เพราะไม่มีอะไรเหลือหลัง
   type erasure — รูปร่างข้อมูลอธิบายด้วยคอมเมนต์ใน `src/lib/derived.js`
   แทน
7. **CSS บางส่วนแปลงเป็น Tailwind utility ไม่ได้** ต้องคงเป็น CSS ปกติใน
   `src/index.css` สามกรณี: (ก) ตัวกรองข้าม tree ผ่าน class บน `<body>`
   (เช่น `body.layer-erp`, `body.hide-direct`, `body.ai-mode`) ที่
   `SvgEdges.jsx` อ่านย้อนกลับจาก DOM โดยตรงเพื่อตัดสินใจว่าจะจางเส้นไหน
   — เปลี่ยนชื่อ class เหล่านี้จะทำให้ลูกศรพังทันที, (ข) เรขาคณิตของโหนด/
   element ที่สร้างด้วย `createElement` ไม่ใช่ JSX (`.fnode`, `.fedge`,
   แถวในทะเบียนฟังก์ชัน), (ค) `::after` content (ป้าย `■ EXIT`) และ
   `:empty` (breadcrumb ยุบเมื่อไม่มีประวัติ) ไม่มีรูปแบบ Tailwind utility
8. **บั๊กเดียวที่แก้ต่างจากต้นฉบับโดยตั้งใจ**: การนับจำนวนฟังก์ชันที่มี
   โอกาส AI ขณะเปิดทะเบียนฟังก์ชันพร้อมกัน ต้นฉบับโยน
   `ReferenceError` — พอร์ตนี้คำนวณให้ถูกต้องแทน (§3.8)
9. **`app.subtitle` เคยมีบั๊กภาษาสลับ** (แก้แล้วในพอร์ตนี้): เดิมค่า
   `th`/`en` ของคีย์นี้สลับกัน (โหมดไทยอ่านชื่ออังกฤษ โหมดอังกฤษอ่านชื่อไทย)
   — เป็นข้อยกเว้นเดียวในทั้งระบบ i18n ที่ทำผิดแบบนี้
10. **ประมาณ 45 ข้อความ UI เคยเป็นภาษาอังกฤษล้วนแม้ตั้งภาษาไทย** — แก้ครบ
    แล้วในพอร์ตนี้ (คีย์ทำเครื่องหมาย `NEW-TH` ใน `src/i18n.js`) รายละเอียด
    ใน §3.9
11. **ต้องมี `.map-scroll { position: relative }`** และ `SvgEdges.jsx`
    ต้องตั้งพิกัด `left`/`top` ของ overlay ใหม่ทุกครั้งที่ redraw — ถ้าลืม
    เงื่อนไขนี้ (เช่นแทรก element ใหม่ระหว่าง wrapper กับ overlay) เส้น
    เชื่อมทั้งหมดจะเลื่อนตำแหน่งผิด (เคยเกิดขึ้นจริงระหว่าง port เพราะ
    `<StageCrumb />` render แทรกอยู่ตรงกลาง)
12. **ไม่มีไลบรารีชาร์ต/กราฟใด ๆ** ทั้ง `SvgEdges.jsx` และ `FocusTrace.jsx`
    เป็น SVG เขียนมือทั้งหมด ตาม `TECH_STACK.md` ที่ห้ามใช้ไลบรารีประเภทนี้
    — การเปลี่ยนไปใช้ไลบรารีในอนาคตต้องเขียน routing logic ใหม่ทั้งหมด
    ไม่ใช่แค่เปลี่ยน syntax
