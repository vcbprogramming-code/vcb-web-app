# VCB Construction — Document Control Hub

A unified document register for VCB Group's active construction projects, plus a sign-in-gated web portal for staff to submit letters and browse what's been logged. Two complementary writers fill the register (an automated Gmail logger and the manual portal), and the portal is also the read interface that the team browses.

Owner account: **c.chavananand@vcb-con.com** (web app runs `executeAs: USER_DEPLOYING`, so the owner's Drive / Gmail / Sheets are the ones the app touches for every user).

---

## What this system does, in one paragraph

Every project site (BT1, VK2, CVE, LPB, BV, PN4, EP, V&K, VC, etc.) emails official documents (memos, approvals, reports) to head office. A self-contained Apps Script time-driven trigger (`gmailAutoLog`, installed via `installGmailAutoLogTrigger()`) fires every 30 minutes and self-gates to 8am–6pm Bangkok — no external cron or session needed — scanning Gmail per project, classifying each new thread by document code (e.g. `BT-02A-036`, `CVE-สำนักงาน-10-043`), logging a row to the master register, and filing the attachment in the right Drive subfolder. Head-office staff can also submit documents through a web portal (`/exec` URL) — for configured projects this auto-generates a fully formatted Thai A4 letterhead Doc + PDF with the next sequential running number, stamps a reference like `BP/บริหาร/01/050`, and writes the same register row. The portal is also where the team browses everything: filter by project / code / status / date, click `Open` to preview the file inline.

### 2. Gmail auto-logger (self-contained Apps Script trigger)
Entirely implemented in [_appsscript_live/Code.js](_appsscript_live/Code.js) — no external skill/cron/session required. `installGmailAutoLogTrigger()` installs a genuine Apps Script time-driven trigger (`ScriptApp.newTrigger('gmailAutoLog').timeBased().everyMinutes(30).create()`) that fires `gmailAutoLog` every 30 minutes around the clock; the function body self-gates to 8am–6pm Bangkok, so it's a no-op outside those hours. A previous, wholly separate automation — a project-root `SKILL.md` (`claude-document-control` skill) that scanned Gmail into a local `.xlsx` via an external Claude-agent cron — has been **deleted**; it was redundant with this trigger and never the app's real data path. To confirm the trigger is actually installed and live, hit the read-only diagnostic route `?action=triggerStatus` on the `/exec` URL — it returns `ScriptApp.getProjectTriggers()` as JSON (handler name + event type).

Per run (`gmailAutoLogRun_` in Code.js):

1. Read known Gmail Thread-IDs already logged, across every project tab of the master register (via `gmailKnownState_`), so already-logged threads are skipped.
2. Search Gmail: Pass A by each project's sender allow-list (`GMAIL_SENDER_GROUPS`), Pass B by subject-prefix patterns (`GMAIL_SUBJECT_QUERIES`) to catch unknown senders too, both OR-combined, windowed to the last 2 days (90 days for `gmailAutoLogFullSync()`).
3. For each new thread: classify by subject prefix first (`GMAIL_PREFIX_RULES`, e.g. `V&K-`, `BR4-`, `BT/`, `BP-`, `EP-`, `VC/`, `VC-`) or sender group, extract the document code (with carve-outs for LPB's slash format and CVE's 4-segment department format), append a row.
4. Save the attachment(s) **directly to the project root folder** via `gmailSaveThreadAttachments_` (resolves the folder by name through `getDocControlFolderMap_`, falling back to `GMAIL_FOLDER_BY_KEY` — no Chrome automation, no My Drive root intermediate); if the Drive save fails, falls back to a `?action=gview` streamed-from-Gmail link so the row still has a clickable Open.
5. Backfill any older rows whose Drive Link is still empty/pending (`state.pending`), and backfill the grey "Summary" 2nd-line snippet on Email-sourced rows logged before that column existed.

There is no separate staging-sheet import, Summary-tab stat recompute, or static-HTML regeneration step — those belonged to the old, now-deleted `SKILL.md` pipeline (see below) and are not part of what `gmailAutoLog` actually does.

Known classifier rules worth remembering:

- **Doc-code extraction:** first whitespace-delimited token of the subject. The category is the segment immediately after the first hyphen following the project prefix — **always preserve a trailing letter** (`02A`, `02B`, `02C`).
- **LPB carve-out:** `VC-LBP/สำนักงาน/08/934` → category is the segment after the third slash (`08`).
- **CVE 4-segment carve-out (added 2026-05-23):** when segment 2 is a Thai department name (`สำนักงาน`, `วิศวะ`, `บริหาร`, `บุคคล`, `บัญชี`), use segment 3 as the code — `CVE-สำนักงาน-10-043` → `10`.
- **Zero-padding:** single-digit codes (`8` → `08`, `1` → `01`).
- **Noise filtering (`gmailIsNoise_`, Code.js):** subject/sender is skipped entirely (never logged, not even under UNCLASSIFIED) when it looks automated — no-reply/do-not-reply/mailer-daemon/postmaster/notification/newsletter/unsubscribe/out-of-office/automatic-reply/n8n/delivery-status addresses, or bank-style payment-confirmation/e-statement subjects that don't also carry a doc-code-shaped `/nn` or `-nn` pattern. This is a generic pattern filter, not a fixed sender allow-list.

### 3. Master register (the data)
One Google Sheet, one tab per project (`BT1`, `VK2`, `CVE`, `LPB`, `BV`, `PN4`, `EP`, `VC`, `UNCLASSIFIED`) plus a `Discussions` tab and a `📊 Summary` rollup.

**Schema (16 columns by header name, NOT position):**
`No.` · `Date Received` · `Time Received` · `Sender Email` · `Document Type` · `Subject` · `Summary` · `Drive Link` · `Project` · `Logged Date` · `Logged Time` · `Gmail Thread-ID` · `Remarks` · `Month` · `Source` · `LetterData`

- `Source` is `Email` (cron-logged) or `Manual` (portal).
- `LetterData` is the JSON the portal stores to re-render the on-screen letter view.
- `Gmail Thread-ID` is the dedup key for the cron; the portal stores `PENDING:<uuid>` until `finalizeLetter` swaps in the Drive Link.

Each project's masthead (company line, address, site/หน่วยงาน, default recipient, closing phrase, signatory) is defined in the `LETTERHEAD` map in [_appsscript_live/Code.js](_appsscript_live/Code.js) (around line 1135; now includes a `VC` entry — หน่วยงาน ลาดหลุมแก้ว ตอน 3, signatory not yet supplied). ## Critical gotchas (must read before editing)

**Canonical master Sheet (after 2026-05-23 recovery):** `1PYXXfMszDoQiQmhPqUimOc5QLIHNK3fjFUtriGHPa1s` — the local `.gsheet` shortcut in this folder. This is what the web app's `MASTER_SHEET_ID` script property points to, and what the cron + portal both read/write. The historical duplicate `1X32T9j0hLbFKH4c24YKI54wl_e58L0c0VjvY86N-BvQ` was deleted when the old Apps Script project was wiped on 2026-05-23, so the consolidation issue is resolved by attrition. Only edit 1PYXX going forward.

**⚠ Drive Link column MUST hold plain URL strings — never `=HYPERLINK("...","Open")` formulas.**
Every row's `docKey` (the unique ID the portal uses to look up a row when "Open" is clicked) comes from the Drive Link cell value via `getValues()`. For a `=HYPERLINK` formula, `getValues()` returns the **display label** (`"Open"`), so every linked row collides on the same key — and `getDocAttachments` returns the *first* matching row's Gmail thread for **every** Open click (symptom: clicking any document shows the same wrong thread ID in the error / viewer). Always use `setValue(url)`, not `setFormula(=HYPERLINK(...))`. If legacy `=HYPERLINK` cells turn up, run `normalizeDriveLinks()` to convert them in-place.

**⚠ `GMAIL_FOLDER_BY_KEY` (Code.js ~line 3467) contains stale folder IDs after a Drive reorg.**
After 2026-05-23 the canonical attachment folders moved (or were re-created) under `H:\My Drive\WORK\06 CORPORATE DOCS\9. DOCUMENT CONTROL\`. `gmailFolderId_()` now resolves folders by **name** via `getDocControlFolderMap_()` first, falling back to the legacy id map only if the canonical parent can't be found. Don't trust the hardcoded ids; trust the name lookup.

**⚠ Deployment is pinned by OAuth redirect URI.** Never run `clasp deploy` without `-i AKfycbxaOHsY…` — a fresh deployment mints a new `/exec` URL that isn't on the OAuth client's authorized redirect URI list, and sign-in breaks immediately for everyone. To update the live app: `clasp push` then `clasp create-deployment -i <SAME id> -d "what changed"`.

**⚠ Web-app access requires vcb-con.com sign-in despite `access: ANYONE`.** Workspace policy overrides the script's own access setting. Anonymous `curl` from outside the domain will redirect to the sign-in page. To execute server-side functions without redeploying:

**2026-06-28 — Session-expiry + "Row not found" + attachment-label fixes.** Deployed in place; live deployment is now **@59** (same `/exec` URL).
- **Session expired even while signed in.** Root cause: `webapp.access` is `ANYONE` + `executeAs: USER_DEPLOYING`, so `Session.getActiveUser().getEmail()` is **blank** — the custom OAuth token is the *only* way the server identifies the user, and its TTL was just **12h**. After it lapsed, every write (`submitDocument` / `finalizeLetter` / `submitDecision`) returned "Session expired" while the client still showed the cached email. Fixes: (1) token TTL **12h → 7 days** ([_appsscript_live/Code.js](_appsscript_live/Code.js) `doGet` sign-in handler); (2) on page load the client now **validates the restored token** via `getReviewerRole(token)` and, if dead, clears auth so the UI shows signed-out instead of a stale email + sticky banner ([_appsscript_live/index.html](_appsscript_live/index.html) restore IIFE). ⚠ The fundamental fix would be `webapp.access: "DOMAIN"` (then `Session` identifies vcb-con.com users and tokens become optional) — **not changed** because it's access-affecting and tied to the 3 access layers; ask the owner first.
- **"Row not found" opening a just-submitted letter.** `docKey_` uses the Drive Link URL as identity, but a letter row is logged link-less and `finalizeLetter` patches the URL in ~10s later — flipping the key. If the row was opened before the list refreshed, the lookup missed. Added `rowMatchesDocId_()` (matches the live key **or** the link-less `proj|subject|date` fallback) and used it in `getDocAttachments`, `findRowMeta_`, and `deleteDocument`.
- **Attachment label on the A4.** Pages appended after the letter (the supplementary attachment) now carry a "📎 เอกสารแนบ (Attachment)" banner so they're not mistaken for part of the letter. Added in `attachPagesHtml()` (client preview/submit) and the `getReview` attachment iframe (review modal).
- **Friendly sign-in prompt (deploy @60).** Per owner: keep access open to **anyone** (staff use personal Gmail; `vcb-con.com` is just the owner's domain) — do NOT restrict to DOMAIN. When a write needs auth, the UI now shows a neutral blue "🔐 please sign in" prompt with a Sign-in button (new `.al-i` style + `needSignIn()`), NOT a red "failed/Session expired" error — nothing is lost, the entries are kept. Applied to the submit dialog (`submitForm` + result handler) and the review modal (reveals its in-panel Sign-in button on lapse). ⚠ For personal-Gmail sign-ins to actually work, the **OAuth consent screen must be External** (Google Cloud Console, project `521733401644`) — if it's Internal, only vcb-con.com accounts can sign in. Not changeable via code.

**2026-06-28 — Review composer redesign (action-first → unified gated composer).** Deployed in place; live deployment was **@57** (same `/exec` URL). The approve / comment / reject panel in the document review modal (`#rvForm` in [_appsscript_live/index.html](_appsscript_live/index.html)) was reworked so the **action is chosen first**, then the note + CC are composed — fixing the old ambiguity where the CC field looked like a peer of the three buttons but was actually a modifier attached to whichever button you pressed.

- **Flow.** Three action buttons up top (💬 Comment / ✓ Approve / ✕ Reject; ↺ Reopen when locked, ↗ Send to Mango ERP when approved — Approve/Reject/Reopen/Mango are manager-only). Type textarea and Draw canvas share a fixed **190px** height so they match (an earlier `flex:1` stretch made the canvas balloon). Gating uses `#rvForm:not(.armed)` rules with `!important` on the hide rules — needed to beat the inline `display` styles on the mode row / canvas — plus a genuinely `disabled` textarea so the box can't be focused or typed in before an action is chosen.
